## 0. aptstack คืออะไร

Portable stack สำหรับ Windows: **PHP + MariaDB + จัดการเวอร์ชันแอป** อยู่โฟลเดอร์เดียว
ไม่ต้องติดตั้ง ไม่แตะ registry ย้ายเครื่องด้วยการ copy

| | XAMPP / Laragon | aptstack |
|---|---|---|
| ติดตั้ง | installer + service | copy โฟลเดอร์ |
| สลับ PHP | ทำมือ เสี่ยงพัง | `aptstack use php 8.3.36` |
| สลับเวอร์ชันแอป | ไม่มี | `aptstack use 1.2.0` + `use -` ย้อนกลับ |
| Windows Service | ติดตั้งมาแล้ว | `aptstack service install` |
| MySQL | ตัวเดียว | แยก datadir ต่อ version **หรือ** ยืมของ XAMPP |
| ช่องโหว่ PHP | ไม่เตือน | `aptstack doctor` |

## 1. ติดตั้งครั้งแรก

```cmd
cd /d D:\aptstack          :: ห้ามมีช่องว่างใน path (แนะนำ)
aptstack init              :: สร้างโครงสร้าง + ติดตั้งตัวอย่าง app (ถ้ายังไม่มี)
aptstack add php <zip>     :: release ไม่ได้แถม PHP -> โหลดเอง (เช่น php-8.3.36-Win32-vs16-x64.zip)
aptstack list              :: ดูของที่มี
aptstack start             :: เปิด database + web
aptstack seed              :: import database ตัวอย่าง (aptstack_demo)
aptstack doctor            :: ตรวจสุขภาพ + ช่องโหว่
```

เปิดเบราว์เซอร์

- ตัวอย่าง app: **http://127.0.0.1:8077/app/** → โชว์ PHP version + ตาราง `greetings`
  (ถ้าเห็นตาราง = **web + PHP + database รันได้จริง**)
- phpMyAdmin: **http://127.0.0.1:8077/phpmyadmin/** (ถ้ามีใน `www\`)
- หน้าทดสอบ PHP: **http://127.0.0.1:8077/**

ถ้าจะลงจากศูนย์ (ยังไม่มีอะไร) ใช้ wizard:

```cmd
powershell -ExecutionPolicy Bypass -File setup.ps1 ^
  -AppDir "C:\deploy\myapp-1.1.0" ^
  -PhpZip "C:\Downloads\php-8.3.36-Win32-vs16-x64.zip"
```

### แบบ offline / intranet (server ไม่มีเน็ต)

`add` **รับ path ท้องถิ่น** อยู่แล้ว — โหลด zip บนเครื่องอื่น แล้ว copy เข้า server:

```cmd
aptstack add php     D:\staging\php-8.3.36-Win32-vs16-x64.zip
aptstack add apache  D:\staging\httpd-2.4.69-261002-Win64-VS18.zip
aptstack add mysql   D:\staging\mariadb-11.4.13-winx64.zip
```

หรือวางเองใน `stack\php\<ver>\` / `stack\apache\<name>\` / `stack\mysql\<name>\` ก็ได้
· มี internal mirror ก็ใช้ URL ภายในได้ · อย่าลืม `vc_redist_x64.exe`
→ ขั้นตอนเต็ม + checksum + checklist: **[OFFLINE-DEPLOY.md](OFFLINE-DEPLOY.md)**

### ตัวอย่าง 3 แอป (ติดตั้งให้ตอนแตกใหม่)

`aptstack init` หรือ `aptstack samples` จะคัดลอกทุกโฟลเดอร์ใน `examples\` ที่มี `index.php`
เข้า `versions\` ให้:

| ชื่อ | ทำอะไร | พิสูจน์ |
|---|---|---|
| `hello-app` | โชว์ PHP/SAPI + ตาราง `greetings` จาก DB | web+PHP+DB เชื่อมกัน |
| `todo-app` | Todolist CRUD จริง (`todo_items`) | **ใช้ database ได้จริง** |
| `sysinfo-app` | inventory: hostname/OS/uptime, **IPv4/subnet/DNS**, CPU, RAM, disk, PHP/Apache/DB | อ่านค่าระบบได้ |

```cmd
aptstack samples      :: ติดตั้งทั้ง 3 (ข้ามตัวที่มีแล้ว)
aptstack seed         :: สร้าง database ให้ (greetings + todo_items)
aptstack next | prev  :: วนดูทีละแอป · use <ชื่อ> = เลือกตรง ๆ · use - = ย้อนกลับ
```

> ✅ **ยืนยันเรื่องที่อยู่:** หลังแตก ZIP ทุกโฟลเดอร์ (`stack\`, `versions\`, `config\`,
> **`data\`**, `logs\`) อยู่ **ภายในโฟลเดอร์ที่แตกทั้งหมด** — ไม่มีการเขียนออกนอกนั้น
> (ยกเว้น `stack\` ที่ต้องใส่ binary เองตอนแรก เพราะ release ไม่แถม)
> · walkthrough เต็มตั้งแต่แตกไฟล์ → **[SCENARIO.md](SCENARIO.md)**

## 2. คำสั่งทั้งหมด

```cmd
aptstack init                    เตรียมโครงสร้าง (versions\ ว่าง -> ลงตัวอย่างให้)
aptstack samples                 ติดตั้งตัวอย่างทั้งหมด (hello / todo / sysinfo)
aptstack list (ls, l)            ดู version + path เต็ม + ที่มา (from:) + แผนที่โฟลเดอร์

aptstack add app <folder|zip> [ชื่อ]  เพิ่มเวอร์ชันแอป -> versions\<ชื่อ>
aptstack add php 8.3.36          เติม URL ทางการ + โหลด + ติดตั้ง (latest ก็ได้)
aptstack add php <zip|url>       หรือส่ง URL/path เอง
aptstack add apache <url|zip>    เพิ่ม Apache     -> stack\apache\<ver>
aptstack add mysql <ver|zip>     เพิ่ม MySQL/MariaDB -> stack\mysql\<ver>
aptstack seed                    สร้าง database ตัวอย่าง (greetings + todo_items)

aptstack use                     เมนูเลือก (แอป + PHP) กดเลข + Enter
aptstack use 1.2.0               สลับแอป + restart ให้เอง
aptstack use 1.2                 ใช้ prefix ก็ได้
aptstack use php 8.3.36          สลับ PHP + restart
aptstack use apache 2.4.69       สลับ Apache + restart
aptstack use mysql 11.4.13       สลับ MySQL (datadir แยกต่อ version)
aptstack use -                   ย้อนกลับตัวก่อนหน้า
aptstack next | prev             วนดูหลายเวอร์ชัน

aptstack start | stop | restart  เปิด/ปิด stack
aptstack status                  รันอยู่ไหม ใช้ version ไหน
aptstack doctor                  ตรวจสุขภาพ + ช่องโหว่
aptstack backup [ชื่อ.sql]       dump ทุก database -> data\dumps\
aptstack logs <apache|mysql|php> ดู log ท้ายไฟล์ (ตัวเลข = กี่บรรทัด)
aptstack logs all                ดู log error ทุกตัว
aptstack report                  สร้างหน้า HTML สรุปสถานะทั้งหมด (เปิดให้ + พิมพ์ได้)

aptstack tls status               ดูสถานะ HTTPS + cert + วันหมดอายุ
aptstack tls init [domain,..]     สร้าง self-signed + เปิด HTTPS + trust ให้
aptstack tls import <c> <k>       ใช้ SSL cert จริง (Let's Encrypt/พาณิชย์)
aptstack tls off                  ปิด HTTPS

aptstack clone app <จาก> <เป็น>  ก้อปปี้โค้ด app (ยังไม่สลับให้ -> use เอง · DB ใช้ตัวเดิม)
aptstack clone mysql <จาก> <เป็น> คัดลอก datadir (ต้อง stop ก่อน + ยืนยัน)
aptstack remove app <ชื่อ>       ลบโค้ด app (ถามยืนยัน · ตัว active ลบไม่ได้)
aptstack remove php|apache|mysql <ชื่อ> [data]  ลบ binary (data เก็บไว้ เว้นแต่ใส่ data)
aptstack migrate mysql <ใหม่>    โยกข้อมูล DB ไป engine ใหม่ (dump -> restore)

aptstack service install         ลง Windows Service (ต้อง admin)
aptstack service uninstall       ถอน
aptstack service start|stop|status
```

ทางลัด: `as list` = `aptstack list`

## 3. เปลี่ยนเวอร์ชันแอป (สำคัญที่สุด)

### หลักการ

```
www\app   =  junction ชี้ไป  versions\<เวอร์ชันที่ใช้อยู่>
```

เปลี่ยนเวอร์ชัน = **ย้าย junction + restart** ของเก่าอยู่ครบ → ย้อนกลับได้เสมอ

### ขั้นตอน deploy เวอร์ชันใหม่

```cmd
:: 1) เตรียม dump ไว้ก่อน (เผื่อต้องย้อน)
aptstack backup

:: 2) copy version ใหม่ลง server
aptstack add app C:\deploy\myapp-1.2.0.zip

:: 3) สลับ
aptstack use 1.2.0

:: 4) ตรวจ
::    เปิดเบราว์เซอร์ดู แล้ว
aptstack doctor
```

### ถ้ามีปัญหา → ย้อนกลับในคำสั่งเดียว

```cmd
aptstack use -        :: กลับไป 1.1.0 ทันที + restart ให้เอง
```

### ทดสอบหลายเวอร์ชันพร้อมกัน

```cmd
aptstack add app \\server\share\build-2026-10-22
aptstack next        :: 1.1.0 -> 2026-10-22
aptstack prev        :: กลับมา
```

### ตั้งชื่อ version อย่างไร? (ไม่มี format บังคับ)

**ชื่อ = ชื่อโฟลเดอร์ใน `versions\`** — ตั้งเองอิสระ 100% ไม่ได้อ่านจาก manifest ที่ไหน

| ที่มาของชื่อ | |
|---|---|
| `aptstack add app <folder> <ชื่อ>` | กำหนดเองตอนเพิ่ม |
| `aptstack add app <zip>` | ชื่อไฟล์ zip (ตัด `.zip`) |
| `aptstack add app examples\todo-app` | ชื่อโฟลเดอร์ต้นทาง |
| copy เองเข้า `versions\` | ชื่อโฟลเดอร์ที่ตั้ง |

แนะนำให้อ่านรู้เรื่องภายหลัง: `1.2.0` (release) · `build-1022` (build รายวัน) ·
`uat` / `staging-hotfix` (สถานะ) · `todo-app` (ชื่อโปรเจกต์)

กติกาที่ควรทำ: **ไม่เว้นวรรค/ไม่มีสัญลักษณ์แปลก** · **อย่าชื่อซ้ำ** (ของเดิมถูกแทนที่เงียบ) ·
**อย่า rename ตัวที่กำลังใช้อยู่** (use ไปตัวอื่นก่อน) · **prefix สั้นอาจชน** (`use 1.2` ถ้ามี
`1.2.0`+`1.2.1` → เอาตัวใหม่สุด) · ยืนยันด้วย `aptstack list` เสมอ

> ฉบับเต็มพร้อมตัวอย่าง → [SCENARIO.md](SCENARIO.md) ข้อ 6

## 4. เปลี่ยน PHP (เรื่องความปลอดภัย)

### รุ่นที่ปลอดภัย

| สาย | ต้องใช้ |
|---|---|
| 8.5 | 8.5.12+ |
| 8.4 | 8.4.27+ |
| 8.3 | **8.3.36+** ← แนะนำ |
| 8.2 | 8.2.35+ |
| ≤8.1 | ❌ EOL ไม่มี patch |

### วิธี

```cmd
:: โหลดจาก https://windows.php.net/downloads/releases/
:: เลือกไฟล์  php-x.y.z-Win32-vs16-x64.zip   (Thread Safe, x64)

aptstack add php C:\Downloads\php-8.3.36-Win32-vs16-x64.zip
aptstack use php 8.3.36
aptstack list        :: ต้องไม่มีคำว่า "ยังไม่ patch" ข้างๆ
aptstack doctor
```

- **Thread Safe (TS)** = ไฟล์ลงท้าย `Win32-vs16-x64` (ไม่ใช่ `-nts-`)
- ของเดิม (`8.1.34`) ยังอยู่ → สลับกลับไปทดสอบโค้ดเก่าได้ด้วย `aptstack use php 8.1.34`
  แต่**ห้ามใช้บน server จริง**

### โค้ดแอปเก่าบน PHP ใหม่ (กรณี CodeIgniter 3)

ถ้าหน้าเว็บขาวหรือขึ้น `Creation of dynamic property ... is deprecated` ให้แก้ที่
`versions\<ver>\index.php` บรรทัด `case 'development':`

```php
error_reporting(E_ALL & ~E_DEPRECATED & ~E_NOTICE & ~E_STRICT);
```

> สาเหตุ: PHP 8.2+ ประกาศ dynamic property เป็น deprecated → CI3 รุ่นเก่าโชว์ error แล้วหยุด request

## 5. เปลี่ยน Apache / MySQL (คำสั่งเดียว เหมือน PHP)

```cmd
:: --- Apache ---
aptstack add apache C:\Downloads\httpd-2.4.69-Win64-VS18.zip
aptstack use apache 2.4.69        :: เลือก + restart ให้เอง

:: --- MySQL / MariaDB ---
aptstack add mysql  C:\Downloads\mariadb-11.4.13-winx64.zip
aptstack use mysql  11.4.13       :: เลือก + restart + ใช้ datadir ของตัวนั้น
```

### web server ที่ใช้อยู่ดูที่ `webMode` (`config\stack.json`)

| ค่า | พฤติกรรม |
|---|---|
| `"auto"` | มี Apache + PHP Thread Safe → ใช้ Apache, ไม่งั้น PHP built-in |
| `"apache"` | บังคับ Apache + `mod_php` (production) |
| `"builtin"` | บังคับ PHP built-in server (dev, single-threaded) |

```cmd
aptstack list        :: มีบรรทัด "Web : apache|builtin"
aptstack doctor      :: ถ้าเป็น apache จะรัน `httpd -t` ให้ด้วย
```

### เงื่อนไขของ mod_php

- PHP ต้องเป็น **Thread Safe** (มี `php8apache2_4.dll`) — `doctor` เตือนให้เอง
- Apache Lounge VS18 ใช้กับ PHP build แบบ `vs16`/`vs17` ได้ (backward compatible)
- โค้ดฝั่งแอป **ไม่ต้องแก้** — แค่ `base_url` ใน config แอปต้องตรง host/port ที่ใช้จริง

### datadir แยกต่อ version

`use mysql <ver>` ชี้ไป `data\<ชื่อเครื่องยนต์>` ของ version นั้น
→ สลับแล้ว **ข้อมูลไม่ปนกัน** และไม่ถูก upgrade โดยไม่ตั้งใจ

## 5a. HTTPS / TLS (self-signed + SSL cert จริง)

**ทำงานได้กับ `webMode=apache` เท่านั้น** (PHP built-in server ไม่รองรับ TLS)

### ทางที่ 1 — สร้าง cert ให้เอง (ทดสอบ/ภายในเครื่อง)

```cmd
aptstack tls init                    :: สร้าง self-signed + เปิด HTTPS + trust ให้เลย
aptstack tls init mysite.local,api.local   :: เพิ่มชื่อ host ใน SAN
aptstack tls status                  :: ดู cert + วันหมดอายุ + trust หรือยัง
```

- ใช้ `openssl.exe` ที่ **มากับ Apache อยู่แล้ว** → ไม่ต้องติดตั้งอะไรเพิ่ม
- ถ้ามี `mkcert` อยู่จะใช้ mkcert แทน (browser เชื่อถือได้ตั้งแต่แรก)
- อายุ 365 วัน, SAN มี `localhost`, `IP:127.0.0.1` + ทุก host ใน `config\vhosts.json`
- **สำคัญ:** สคริปต์จะ **ใส่ cert เข้า Trusted Root ของผู้ใช้ให้ด้วย**
  เพราะถ้าไม่ trust → .NET/browser จะปฏิเสธ (UntrustedRoot)
  (การปลดด้วย `ServerCertificateValidationCallback` ใช้ไม่ได้จริงบน PS 5.1 — ทดสอบแล้ว)

### ทางที่ 2 — ใช้ SSL cert จริง (Let's Encrypt / ผู้ให้บริการ)

```cmd
aptstack tls import C:\certs\fullchain.pem C:\certs\privkey.pem
```

- คัดลอกเข้า `config\certs\` แล้วเปิด HTTPS ให้เอง
- แสดง subject / วันหมดอายุ / เตือนถ้าเหลือ < 14 วัน
- **cert จริงไม่ต้องเข้า Trusted Root** (CA เชื่อถืออยู่แล้ว)
- ต่ออายุแล้วรัน `tls import` ใหม่ → `restart` ให้อัตโนมัติ

```cmd
aptstack tls off        :: ปิด HTTPS
aptstack tls status     :: สถานะปัจจุบัน
```

| config (`config\stack.json`) | ค่าเริ่มต้น |
|---|---|
| `httpsEnabled` | `false` |
| `httpsPort` | `8443` |
| `certFile` / `keyFile` | เติมให้เองโดย `tls init/import` |
| `serverName` | `localhost` |

> เปิดดู: `https://127.0.0.1:8443/` — health probe ตอน `start` จะเช็ค HTTPS ให้ด้วย
> ถ้า fail `doctor` จะรายงาน `[ERR]`

## 5b. Virtual hosts (`config\vhosts.json`)

แยกหลายแอป/หลายชื่อ host บน Apache ตัวเดียวกัน:

```json
[
  { "host": "demo.local", "app": "hello-1.0.0" },
  { "host": "apt.local",  "app": "1.1.0" },
  { "host": "old.local",  "app": "1.0.0", "https": false }
]
```

| ฟิลด์ | บังคับ | หมายเหตุ |
|---|---|---|
| `host` | ✅ | ชื่อ host |
| `app` | ❌ | ชื่อใน `versions\` (ว่าง = ใช้ตัวที่ active อยู่) |
| `port` | ❌ | ค่าเริ่มต้น = `httpPort` (8077) |
| `https` | ❌ | เมื่อเปิด HTTPS จะออก vhost ฝั่ง https **ให้ทุกตัวอัตโนมัติ**<br>ใส่ `"https": false` ถ้าไม่ต้องการ |

```cmd
aptstack restart        :: generate config\httpd.conf ใหม่ (httpd -t ให้เอง)
aptstack doctor         :: ตรวจนับ vhost + ตรวจว่า app มีอยู่จริง
```

**ต้องเพิ่มใน hosts file** ของ Windows (`C:\Windows\System32\drivers\etc\hosts`):

```
127.0.0.1   demo.local apt.local
```

> ⚠️ **ข้อควรระวังของ Apache:** พอเพิ่ม `<VirtualHost>` ตัวแรกใน port นั้น
> Apache จะใช้ **vhost ตัวแรกเป็น default** — aptstack ใส่
> `<VirtualHost *:port>` ชี้ไป `www\` **ไว้ก่อนเสมอ** จึงไม่ทำให้
> `http://127.0.0.1:8077/` เพี้ยน (ทดสอบแล้ว: default/demo.local/apt.local แยกกันถูก)
>
> ข้อจำกัด: virtual host ใช้ได้กับ `webMode=apache` เท่านั้น

## 5c. จัดการ version: clone / remove / migrate / report

```cmd
:: ก้อปปี้โค้ด app -> ยังอยู่เวอร์ชันเดิมจนกว่าจะสั่ง use (DB ใช้ตัวเดิมเสมอ)
aptstack clone app 1.0 1.1
aptstack use 1.1            :: เมื่อพร้อม

:: คัดลอก datadir (บังคับ stop — ไฟล์ InnoDB ห้าม copy ตอนเปิด)
aptstack stop
aptstack clone mysql mariadb-11.4.13 mariadb-11.4.14

:: โยกข้อมูลไป engine ใหม่: dump -> stop -> switch -> start -> restore
:: (ของเดิมไม่ถูกแตะ -> ย้อนกลับได้: aptstack use mysql <เดิม>)
aptstack add mysql 10.11.19
aptstack migrate mysql 10.11.19

:: ลบ — ถามยืนยันเสมอ + ตัวที่ active ลบไม่ได้ + กัน path traversal
aptstack remove app 1.0
aptstack remove php 8.1.34
aptstack remove mysql mariadb-11.4.13          :: เก็บ data ไว้ (แนะนำ)
aptstack remove mysql mariadb-11.4.13 data     :: ลบทั้งคู่ (ต้องพิมพ์ DELETE)

:: รายงานสถานะทั้งหมดเป็น HTML (เปิดเบราว์เซอร์ให้ + Ctrl+P พิมพ์ A4)
aptstack report
```

**หลักการสำคัญ**

- **DB ไม่ผูกกับแอป** — ค่า host/port/user/pass อยู่กลางที่ `config\stack.json`
  → clone แอปใหม่เห็นข้อมูลชุดเดิมทันที (ถ้าจะแยก DB ต่อแอป ให้ย้ายไป config ของแอปเอง)
- **datadir แยกต่อ engine** → `clone mysql` ใช้ตอนจะลอง engine ใหม่โดยยังเก็บของเดิมไว้
- **migrate = dump/restore (logical)** ไม่ใช่ copy ไฟล์ → ปลอดภัยกว่าและข้ามเวอร์ชัน engine ได้
- คำสั่งที่ทำลายของจริง **ต้องยืนยัน** (`y` / `DELETE`) — รันแบบ non-interactive ที่ไม่ตอบ = ยกเลิกเอง

> help ทุกคำสั่ง: `aptstack help` · `-h` · `--help` · `/?` (แต่ต้องเรียกผ่าน `.cmd`)

## 6. ใช้ MySQL ของ XAMPP แทน MariaDB ของ aptstack

แก้ `config\stack.json`:

```json
{
  "dbMode": "external",
  "dbPort": 3306,
  "httpPort": 8077
}
```

แล้ว `aptstack restart`

- aptstack จะ**ไม่ start / ไม่ stop / ไม่ kill** MySQL ของ XAMPP
- web + phpMyAdmin ยังรันจาก aptstack (port 8077)
- อย่าลืมให้ phpMyAdmin ชี้ port ตรงกับ `dbPort` (ดู `www\phpmyadmin\config.inc.php`)

| ต้องการ | ตั้งค่า |
|---|---|
| MariaDB ของเราเอง (ค่าเริ่มต้น) | `"dbMode": "internal"`, `"dbPort": 3307` |
| ยืม MySQL ของ XAMPP | `"dbMode": "external"`, `"dbPort": 3306` |
| ไม่มี database เลย | `"dbMode": "external"` + port ที่ไม่มีใครใช้ |

> ⚠️ `dbMode=internal` กับ XAMPP พร้อมกัน → ชนกันแน่นอน ถ้า XAMPP เปิด port 3306
> ให้ aptstack ใช้ 3307 (ค่าเริ่มต้น) หรือเป็น `external` ไปเลย

## 7. Windows Service

```cmd
:: เปิด cmd ด้วยสิทธิ์ administrator
aptstack service install
aptstack service start
aptstack service status
```

- compile ตัว service เองด้วย `csc.exe` ที่มากับ Windows → **ไม่ต้องโหลด NSSM/WinSW**
- source อยู่ที่ `service\AptStackService.cs` → ได้ `bin\aptstack-svc.exe`
- register ด้วย `sc create AptStack ... start= auto` + `sc failure` ให้ restart อัตโนมัติถ้าล่ม
- ปิด stack แบบ clean (แตะ `config\stop.flag` แล้วรอ) ก่อน kill

```cmd
aptstack service uninstall    :: ถอน (admin)
```

> ถ้า `csc.exe` ไม่มี → ติดตั้ง .NET Framework 4.x มาก่อน

## 7b. โหมด dev vs production (manual vs Windows Service)

**ไม่ใช้ nginx** — aptstack มี web engine แค่ 2 แบบ: **Apache + mod_php** หรือ **PHP built-in server**
(เลือกด้วย `webMode` ใน `config\stack.json`)

### DEV (Windows 11 notebook) — ไม่ต้อง register service เลย

```cmd
aptstack start        :: เปิด stack แบบ manual
aptstack run          :: แบบเดียวกัน แต่ค้างหน้าจอ กด Ctrl+C หยุด
aptstack stop
```

- ไม่ต้องเปิด admin, ไม่ต้องติดตั้ง service
- เปลี่ยนรุ่นทดสอบได้ทันที: `use php 8.1.34` → `use php 8.3.36` → `use -`
- เก็บหลักฐานส่ง auditor: `aptstack doctor` + `aptstack report`

### PRODUCTION (Windows Server) — รัน manual ก่อนได้ แล้วค่อยทำ service ทีหลัง

```cmd
:: ขั้นที่ 1 — ลองรันแบบ manual (เหมือน dev)
aptstack use todo-1.1
aptstack start
aptstack doctor            :: ต้องไม่มี [ERR]

:: ขั้นที่ 2 — มั่นใจแล้ว ค่อยให้บูตเอง (ต้อง Run as admin)
aptstack service install
aptstack service start
```

- `service install` **ไม่บังคับ** — ใช้ `start`/`run` บน server ก็ได้ตลอด
- ถ้าติดตั้ง service ตอน stack manual ยังรันอยู่ → **ระบบเตือน** ให้ `aptstack stop` ก่อน
  (กันตอนบูตแล้วชนพอร์ต)
- ถอน service: `aptstack service uninstall` (ไม่เหลืออะไรค้าง)

### เคสจริง: dev บน notebook แล้วเอาไป server ที่ไม่มีเน็ต

```cmd
:: บน notebook
aptstack dist todo-1.1        :: สร้าง dist_paste\todo-1.1\ (มี VERSIONS.txt + DEPLOY.txt)

:: copy ไป server ด้วย RDP drive / USB / share  (ดู OFFLINE-DEPLOY.md)
:: บน server
cd /d E:\todo-1.1
aptstack use todo-1.1
aptstack start
aptstack doctor
aptstack service install && aptstack service start   :: ถ้าอยากให้บูตเอง
```

ภาพรวมทั้งหมด → [diagrams.md](diagrams.md) · ขั้นตอนละเอียด → [SCENARIO.md](SCENARIO.md)

## 8. ย้ายไปเครื่อง server

> **server ไม่มีเน็ต / intranet?** → ดู **[OFFLINE-DEPLOY.md](OFFLINE-DEPLOY.md)**
> (โหลด binary บนเครื่องอื่น แล้ว copy เข้า server พร้อม checksum + checklist)
> ส่วนขั้นตอนล่างนี้คือ "ย้ายทั้งโฟลเดอร์" ที่เครื่อง source มีของอยู่ครบแล้ว

```cmd
:: บนเครื่อง dev
aptstack stop
aptstack backup            :: เอา dump ไปด้วย

:: copy ทั้งโฟลเดอร์ไป (ยกเว้น .git ถ้าไม่อยากเอา)
robocopy D:\aptstack E:\aptstack /E /XD .git downloads

:: บน server
cd /d E:\aptstack
aptstack start
aptstack doctor            :: ต้องไม่มี [ERR]
```

ทำไมไม่พังเรื่อง path → เพราะ `config\php.ini` และ `config\my.ini`
**ถูก generate ใหม่ทุกครั้งที่ start** โดยคำนวณ path จากตำแหน่งที่รันจริง

## 9. แก้ปัญหา

| อาการ | สาเหตุ | แก้ |
|---|---|---|
| หน้าแอปขาว / `mysqli_connect() undefined` | extension ไม่โหลด | `aptstack restart` |
| `aptstack logs php` เตือน `Unable to load dynamic library` | ใต้ Apache ไม่รู้ PATH ของ PHP | `aptstack restart` (เวอร์ชัน 1.1.0+ แก้ให้แล้ว) |
| HTTPS ไม่ตอบ / `UntrustedRoot` | cert ยังไม่ได้ trust | `aptstack tls init` (ใส่ Trusted Root ให้เอง) |
| browser แจ้ง `NET::ERR_CERT_COMMON_NAME_INVALID` | cert ไม่มีชื่อ host นั้นใน SAN | `aptstack tls init <ชื่อhost>` ใหม่ |
| `openssl ... Can't open C:\Apache24\conf\openssl.cnf` | path compile-time | สคริปต์ชี้ `OPENSSL_CONF` ให้แล้ว (1.1.0+) — รัน `tls init` ซ้ำ |
| `SSLSessionCache: cache size not numerical` | build นี้ไม่รับ `shmcb` | ถูกตัดออกจาก template แล้ว (1.1.0+) |
| `https://ชื่อhost/` ตกหน้า default | ยังไม่มี vhost ฝั่ง https | เพิ่ม host ใน `config\vhosts.json` แล้ว restart |
| vhost ไม่ถูกเรียกตามชื่อ | ยังไม่ได้เพิ่ม hosts file | เพิ่ม `127.0.0.1 <host>` แล้วรัน `aptstack doctor` ดูบรรทัดที่บอก |
| `Unable to load dynamic library` ใน log | `extension_dir` ผิด | `aptstack restart` (generate ใหม่) |
| พอร์ตชน | โปรแกรมอื่นจองไว้ | แก้ `httpPort`/`dbPort` ใน `config\stack.json` |
| MariaDB ไม่ขึ้น | datadir/permission | ดู `logs\mariadb-error.log` |
| Web ไม่ขึ้น | port/ini | ดู `logs\php-error.log` |
| เปลี่ยน php.ini แล้วไม่เห็นผล | ถูก generate ทับ | แก้ที่ `templates\` แล้ว restart |
| `aptstack` ไม่รู้จัก | อยู่ผิดโฟลเดอร์ | `cd` มาก่อน หรือใช้ `as` |
| ExecutionPolicy error | — | ใช้ `aptstack.cmd` (bypass ให้แล้ว) |
| อยากดูว่ารัน PHP ตัวไหน | — | `aptstack status` หรือ `aptstack list` |

**ดู log**

```cmd
notepad logs\php-error.log
notepad logs\mariadb-error.log
```

## 11. โครงสร้างไฟล์

```
aptstack\
├── aptstack.cmd / as.cmd       entry
├── aptstack.ps1                logic ทั้งหมด
├── setup.ps1                   wizard
├── service.ps1                 Windows Service
├── service\AptStackService.cs  source ของ service host
│
├── examples\                    ✅ ตัวอย่าง 3 แอป + seed.sql (commit ลง git)
│   ├── hello-app\index.php        โชว์ PHP + ตาราง greetings
│   ├── todo-app\index.php         Todolist CRUD (ใช้ database จริง)
│   ├── sysinfo-app\index.php      inventory เครื่อง (IP/subnet/CPU/RAM)
│   ├── seed.sql                   สร้างด้วย: aptstack seed
│   └── vhosts.sample.json         ตัวอย่าง config virtual host
│
├── templates\                  ✅ ต้นฉบับ (แก้ตรงนี้, commit ลง git)
│   ├── php-extensions.ini
│   ├── php-hardening.ini
│   ├── my.ini.tpl
│   ├── httpd.conf.tpl             (ใช้เมื่อ webMode=apache)
│   └── ssl.conf.tpl               (ใช้เมื่อ httpsEnabled=true)
│
├── config\                     ⚠️ config ทั้งหมดอยู่ที่เดียว (gitignore)
│   ├── stack.json                ★ เลือก version + port + httpsEnabled
│   ├── vhosts.json               ★ virtual host (ดูข้อ 5b)
│   ├── certs\                    ★ cert/key ของ TLS (tls init / tls import)
│   ├── php.ini, my.ini, httpd.conf   generate ใหม่ทุก start (ห้ามแก้)
│   └── pids\  tmp\  stop.flag
│
├── stack\                      binary (gitignore)
│   ├── php\8.3.36\  php\8.1.34\
│   ├── apache\httpd-2.4.69\
│   └── mysql\mariadb-11.4.13-winx64\
│
├── versions\                   โค้ดแอป (gitignore)  hello-app\ todo-app\ sysinfo-app\ 1.1.0\
├── data\                       database (gitignore)
│   ├── mariadb-11.4.13-winx64\   datadir
│   └── dumps\                     *.sql
│
├── www\                        docroot
│   ├── router.php  ✅
│   ├── phpmyadmin\
│   └── app    junction -> versions\<active>
│
├── logs\  downloads\  bin\
└── docs\                       คู่มือ (คู่มือ.md/.html, SCENARIO.md, OFFLINE-DEPLOY.md, ...)
```

**กฎทอง:** `templates\` = ต้นฉบับ · `config\` = ค่าที่ generate · `stack\` = binary ·
`versions\` = โค้ด · `data\` = ข้อมูล
