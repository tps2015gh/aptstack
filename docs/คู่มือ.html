0. aptstack คืออะไร

Portable stack สำหรับ Windows: PHP + MariaDB + จัดการเวอร์ชันแอป อยู่โฟลเดอร์เดียว ไม่ต้องติดตั้ง ไม่แตะ registry ย้ายเครื่องด้วยการ copy

XAMPP / Laragonaptstack
ติดตั้งinstaller + servicecopy โฟลเดอร์
สลับ PHPทำมือ เสี่ยงพังaptstack use php 8.3.36
สลับเวอร์ชันแอปไม่มีaptstack use 1.2.0 + use -
Windows Serviceติดตั้งมาแล้วaptstack service install
MySQLตัวเดียวแยก datadir / ยืมของ XAMPP ได้
ช่องโหว่ PHPไม่เตือนaptstack doctor

1. ติดตั้งครั้งแรก

cd /d D:\aptstack          :: ห้ามมีช่องว่างใน path (แนะนำ)
aptstack init              :: สร้างโครงสร้าง + ติดตั้งตัวอย่าง app
aptstack add php <zip>     :: release ไม่ได้แถม PHP -> โหลดเอง
aptstack start             :: เปิด database + web
aptstack seed              :: import database ตัวอย่าง
aptstack doctor            :: ตรวจสุขภาพ + ช่องโหว่
เปิดเบราว์เซอร์
ตัวอย่าง app: http://127.0.0.1:8077/app/ → โชว์ PHP version + ตาราง greetings (เห็นตาราง = web + PHP + database รันได้จริง)
phpMyAdmin: http://127.0.0.1:8077/phpmyadmin/ · หน้าทดสอบ PHP: http://127.0.0.1:8077/

ลงจากศูนย์ด้วย wizard:

powershell -ExecutionPolicy Bypass -File setup.ps1 ^
  -AppDir "C:\deploy\myapp-1.1.0" ^
  -PhpZip "C:\Downloads\php-8.3.36-Win32-vs16-x64.zip"
แบบ offline / intranet (server ไม่มีเน็ต) — add รับ path ท้องถิ่น อยู่แล้ว:
aptstack add php D:\staging\php-8.3.36-Win32-vs16-x64.zip
หรือวางเองใน stack\php\<ver>\ · มี mirror ภายในก็ใช้ URL ภายในได้
ขั้นตอนเต็ม + checksum + checklist → docs/OFFLINE-DEPLOY.md
ตัวอย่าง 3 แอป (ติดตั้งให้ตอนแตกใหม่ ด้วย aptstack init หรือ aptstack samples)
hello-app โชว์ PHP + ตาราง greetings · todo-app Todolist CRUD ใช้ database จริง · sysinfo-app inventory (IPv4/subnet/CPU/RAM/disk/PHP/Apache/DB)
แล้วสลับด้วย aptstack use <ชื่อ> / next / prev / use - · เริ่ม: aptstack seed ก่อนใช้ todolist

✅ ยืนยันเรื่องที่อยู่: หลังแตก ZIP ทุกโฟลเดอร์ (stack\, versions\, config\, data\, logs\) อยู่ ภายในโฟลเดอร์ที่แตกทั้งหมด (ยกเว้น stack\ ที่ต้องใส่ binary เองตอนแรก)
walkthrough เต็ม → docs/SCENARIO.md

2. คำสั่งทั้งหมด

aptstack init                    เตรียมโครงสร้าง (versions\ ว่าง -> ลงตัวอย่างให้)
aptstack samples                 ติดตั้งตัวอย่างทั้งหมด (hello / todo / sysinfo)
aptstack list (ls, l)            ดู version + path เต็ม + ที่มา (from:) + แผนที่โฟลเดอร์

aptstack add app <folder|zip> [ชื่อ]  เพิ่มเวอร์ชันแอป -> versions\<ชื่อ>
aptstack add php 8.3.36          เติม URL ทางการ + โหลด + ติดตั้ง (latest ก็ได้)
aptstack add php <zip|url>       หรือส่ง URL/path เอง
aptstack add apache <url|zip>    เพิ่ม Apache     -> stack\apache\<ver>
aptstack add mysql <ver|zip>     เพิ่ม MySQL/MariaDB -> stack\mysql\<ver>
aptstack seed                    สร้าง database ตัวอย่าง (greetings + todo_items)
aptstack report                  สร้างหน้า HTML สรุปสถานะ (เปิดให้ + พิมพ์ได้ Ctrl+P)

aptstack use                     เมนูเลือก (แอป + PHP) กดเลข + Enter
aptstack use 1.2.0               สลับแอป + restart ให้เอง
aptstack use 1.2                 ใช้ prefix ก็ได้
aptstack use php 8.3.36          สลับ PHP + restart
aptstack use apache 2.4.69       สลับ Apache + restart
aptstack use mysql 11.4.13       สลับ MySQL (datadir แยกต่อ version)
aptstack use -                   ย้อนกลับตัวก่อนหน้า
aptstack next | prev             วนดูหลายเวอร์ชัน

aptstack start | stop | restart  เปิด/ปิด stack
aptstack status                  รันอยู่ไหม ใช้ version ไหน
aptstack doctor                  ตรวจสุขภาพ + ช่องโหว่
aptstack backup [ชื่อ.sql]       dump ทุก database -> data\dumps\
aptstack seed                    import database ตัวอย่าง (aptstack_demo)
aptstack logs <apache|mysql|php> ดู log ท้ายไฟล์ (ตัวเลข = กี่บรรทัด)
aptstack logs all                ดู log error ทุกตัว

aptstack tls status               ดูสถานะ HTTPS + cert + วันหมดอายุ
aptstack tls init [domain,..]     สร้าง self-signed + เปิด HTTPS + trust
aptstack tls import <c> <k>       ใช้ SSL cert จริง (Let's Encrypt/พาณิชย์)
aptstack tls off                  ปิด HTTPS

aptstack clone app <จาก> <เป็น>  ก้อปปี้โค้ด app (ยังไม่สลับให้ -> use เอง · DB ใช้ตัวเดิม)
aptstack clone mysql <จาก> <เป็น> คัดลอก datadir (ต้อง stop ก่อน + ยืนยัน)
aptstack remove app <ชื่อ>       ลบโค้ด app (ถามยืนยัน · ตัว active ลบไม่ได้)
aptstack remove php|apache|mysql <ชื่อ> [data]  ลบ binary (data เก็บไว้ เว้นแต่ใส่ data)
aptstack migrate mysql <ใหม่>    โยกข้อมูล DB ไป engine ใหม่ (dump -> restore)

aptstack service install         ลง Windows Service (ต้อง admin)
aptstack service uninstall       ถอน
aptstack service start|stop|status

ทางลัด: as list = aptstack list

3. เปลี่ยนเวอร์ชันแอป (สำคัญที่สุด)

หลักการ

www\app   =  junction ชี้ไป  versions\<เวอร์ชันที่ใช้อยู่>

เปลี่ยนเวอร์ชัน = ย้าย junction + restart ของเก่าอยู่ครบ → ย้อนกลับได้เสมอ

ขั้นตอน deploy เวอร์ชันใหม่

aptstack backup                              :: 1) เผื่อต้องย้อน
aptstack add app C:\deploy\myapp-1.2.0.zip   :: 2) copy version ใหม่ลง
aptstack use 1.2.0                           :: 3) สลับ + restart ให้เอง
:: 4) เปิดเบราว์เซอร์ดู แล้ว
aptstack doctor
มีปัญหา → ย้อนกลับในคำสั่งเดียว 
aptstack use -        :: กลับไปตัวเมื่อกี้ทันที + restart ให้เอง

ทดสอบหลายเวอร์ชัน

aptstack add app \\server\share\build-2026-10-22
aptstack next        :: 1.1.0 -> 2026-10-22
aptstack prev        :: กลับมา

ตั้งชื่อ version อย่างไร? (ไม่มี format บังคับ)

ชื่อ = ชื่อโฟลเดอร์ใน versions\ — ตั้งเองอิสระ 100% ไม่ได้อ่านจาก manifest ที่ไหน

ที่มาของชื่อ
aptstack add app <folder> <ชื่อ>กำหนดเองตอนเพิ่ม
aptstack add app <zip>ชื่อไฟล์ zip (ตัด .zip)
aptstack add app examples\todo-appชื่อโฟลเดอร์ต้นทาง
copy เองเข้า versions\ชื่อโฟลเดอร์ที่ตั้ง

แนะนำให้อ่านรู้เรื่องภายหลัง: 1.2.0 (release) · build-1022 (build) · uat/staging-hotfix (สถานะ) · todo-app (ชื่อโปรเจกต์)

กติกาที่ควรทำ: ไม่เว้นวรรค/ไม่มีสัญลักษณ์แปลก · อย่าชื่อซ้ำ (ของเดิมถูกแทนที่เงียบ) · อย่า rename ตัวที่กำลังใช้อยู่ (use ไปตัวอื่นก่อน) · prefix สั้นอาจชน (use 1.2 ถ้ามี 1.2.0+1.2.1 → เอาตัวใหม่สุด) · ยืนยันด้วย aptstack list

4. เปลี่ยน PHP (เรื่องความปลอดภัย)

สาย PHPต้องใช้
8.58.5.12+
8.48.4.27+
8.38.3.36+ ← แนะนำ
8.28.2.35+
≤8.1EOL ไม่มี patch — ห้ามใช้ production
aptstack add php C:\Downloads\php-8.3.36-Win32-vs16-x64.zip
aptstack use php 8.3.36
aptstack list        :: ต้องไม่มีคำว่า "ยังไม่ patch"
aptstack doctor
  • Thread Safe (TS) = ไฟล์ลงท้าย Win32-vs16-x64 (ไม่ใช่ -nts-)
  • ของเดิม 8.1.34 ยังอยู่ → สลับกลับทดสอบโค้ดเก่าได้ แต่ห้ามใช้บน server จริง
โค้ดแอปเก่า (CodeIgniter 3) บน PHP 8.2+ — ถ้าหน้าขาวหรือขึ้น Creation of dynamic property ... is deprecated ให้แก้ที่ versions\<ver>\index.php บรรทัด case 'development': 
error_reporting(E_ALL & ~E_DEPRECATED & ~E_NOTICE & ~E_STRICT);

4b. เปลี่ยน Apache / MySQL (คำสั่งเดียว)

aptstack add apache C:\Downloads\httpd-2.4.69-Win64-VS18.zip
aptstack use apache 2.4.69       :: เลือก + restart ให้เอง

aptstack add mysql  C:\Downloads\mariadb-11.4.13-winx64.zip
aptstack use mysql  11.4.13      :: เลือก + restart + datadir ของตัวนั้น
webMode ใน config\stack.jsonพฤติกรรม
"auto"มี Apache + PHP Thread Safe → ใช้ Apache, ไม่งั้น built-in
"apache"บังคับ Apache + mod_php (production)
"builtin"บังคับ PHP built-in (dev, single-threaded)
mod_php ต้องใช้ PHP Thread Safe (มี php8apache2_4.dll) — doctor เตือนให้เอง และรัน httpd -t ตรวจ syntax ให้ด้วย
โค้ดแอป ไม่ต้องแก้ แค่ base_url ตรง host/port จริง
datadir แยกต่อ version — use mysql <ver> ชี้ไป data\<ชื่อเครื่องยนต์> → ข้อมูลไม่ปนกัน ไม่ถูก upgrade โดยไม่ตั้งใจ

5. ใช้ MySQL ของ XAMPP แทน MariaDB ของ aptstack

แก้ config\stack.json:

{
  "dbMode": "external",
  "dbPort": 3306,
  "httpPort": 8077
}

แล้ว aptstack restart

  • aptstack จะไม่ start / ไม่ stop / ไม่ kill MySQL ของ XAMPP
  • web + phpMyAdmin ยังรันจาก aptstack (port 8077)
  • อย่าลืมให้ phpMyAdmin ชี้ port ตรงกับ dbPort
ต้องการตั้งค่า
MariaDB ของเราเอง (ค่าเริ่มต้น)"dbMode":"internal", "dbPort":3307
ยืม MySQL ของ XAMPP"dbMode":"external", "dbPort":3306
⚠️ ถ้า XAMPP เปิด port 3306 อยู่ อย่าใช้ dbMode:internal กับ 3306 — ชนกันแน่นอน

5a. HTTPS / TLS (self-signed + SSL cert จริง)

ใช้ได้กับ webMode=apache เท่านั้น (PHP built-in ไม่รองรับ TLS)

ทางที่ 1 — ให้ aptstack สร้าง cert (ทดสอบ/ภายในเครื่อง)

aptstack tls init                    :: สร้าง + เปิด HTTPS + trust ให้เลย
aptstack tls init mysite.local,api.local
aptstack tls status                  :: ดู cert + หมดอายุ + trust หรือยัง
  • ใช้ openssl.exe ที่มากับ Apache อยู่แล้ว → ไม่ต้องติดตั้งอะไรเพิ่ม (ถ้ามี mkcert จะใช้ mkcert แทน)
  • อายุ 365 วัน · SAN มี localhost, IP:127.0.0.1 และทุก host ใน vhosts.json
  • สำคัญ: จะใส่ cert เข้า Trusted Root ของผู้ใช้ให้ด้วย เพราะถ้าไม่ trust → .NET/browser ปฏิเสธ UntrustedRoot (การปลดด้วย ServerCertificateValidationCallback ใช้ไม่ได้จริงบน PS 5.1 — ทดสอบแล้ว)

ทางที่ 2 — ใช้ SSL cert จริง

aptstack tls import C:\certs\fullchain.pem C:\certs\privkey.pem
aptstack tls off
  • คัดลอกเข้า config\certs\ แล้วเปิด HTTPS ให้เอง + restart
  • แสดง subject / หมดอายุ / เตือนถ้าเหลือ < 14 วัน
  • cert จริงไม่ต้องเข้า Trusted Root (CA เชื่อถืออยู่แล้ว)
  • ต่ออายุ → tls import ใหม่
เปิดดู https://127.0.0.1:8443/ — start จะ health probe HTTPS ให้ และ doctor จะรายงานถ้า fail

5b. Virtual hosts (config\vhosts.json)

[
  { "host": "demo.local", "app": "hello-1.0.0" },
  { "host": "apt.local",  "app": "1.1.0" },
  { "host": "old.local",  "app": "1.0.0", "https": false }
]
aptstack restart      :: generate config\httpd.conf ใหม่ (httpd -t ให้เอง)
aptstack doctor       :: ตรวจนับ vhost + ตรวจว่า app มีอยู่จริง

ต้องเพิ่มใน hosts file (C:\Windows\System32\drivers\etc\hosts):

127.0.0.1   demo.local apt.local
ข้อควรระวัง: พอเพิ่ม <VirtualHost> ตัวแรกของ port นั้น Apache จะใช้ vhost ตัวแรกเป็น default — aptstack ใส่ default vhost ชี้ www\ ไว้ก่อนเสมอ จึงไม่ทำให้ http://127.0.0.1:8077/ เพี้ยน (ทดสอบแล้ว แยกถูกทั้ง default/demo/apt)
ข้อจำกัด: ใช้ได้กับ webMode=apache เท่านั้น

5c. จัดการ version: clone / remove / migrate / report

:: ก้อปปี้โค้ด app -> ยังอยู่เวอร์ชันเดิมจนกว่าจะสั่ง use (DB ใช้ตัวเดิมเสมอ)
aptstack clone app 1.0 1.1
aptstack use 1.1                 :: เมื่อพร้อม

:: คัดลอก datadir (บังคับ stop — ไฟล์ InnoDB ห้าม copy ตอนเปิด)
aptstack stop
aptstack clone mysql mariadb-11.4.13 mariadb-11.4.14

:: โยกข้อมูลไป engine ใหม่ (dump -> switch -> restore · ของเดิมไม่ถูกแตะ)
aptstack migrate mysql 10.11.19

:: ลบ — ถามยืนยันเสมอ · ตัว active ลบไม่ได้ · กัน path traversal
aptstack remove app 1.0
aptstack remove mysql mariadb-11.4.13 data   :: ต้องพิมพ์ DELETE

:: รายงานสถานะเป็น HTML (เปิดให้ + Ctrl+P พิมพ์ A4)
aptstack report
หลักการสำคัญ
• DB ไม่ผูกกับแอป — ค่า host/port/user/pass อยู่กลางที่ config\stack.json → clone แอปใหม่เห็นข้อมูลชุดเดิมทันที
• datadir แยกต่อ engine → clone mysql ใช้ตอนลอง engine ใหม่โดยยังเก็บของเดิม
• migrate = dump/restore (logical) ไม่ใช่ copy ไฟล์ → ข้ามเวอร์ชัน engine ได้ + rollback ได้
• คำสั่งทำลายของจริง ต้องยืนยัน (y / DELETE) — ไม่มี stdin = ยกเลิกเอง
• help: aptstack help · -h · --help (แต่ต้องเรียกผ่าน .cmd)

6. Windows Service

:: เปิด cmd ด้วยสิทธิ์ administrator
aptstack service install
aptstack service start
aptstack service status
  • compile เองด้วย csc.exe ที่มากับ Windows → ไม่ต้องโหลด NSSM/WinSW
  • source อยู่ที่ service\AptStackService.cs → ได้ bin\aptstack-svc.exe
  • register ด้วย sc create + sc failure ให้ restart อัตโนมัติถ้าล่ม
  • ปิด stack แบบ clean (แตะ config\stop.flag แล้วรอ) ก่อน kill
aptstack service uninstall    :: ถอน (admin)

9. ความปลอดภัย

aptstack doctor

ตรวจให้ครบ:

  • PHP ตรงเกณฑ์ patch ช่องโหว่ RCE หรือยัง (security-php.txt)
  • session.upload_progress ปิด / expose_php / allow_url_include / display_errors ปิด
  • ถ้ายัง patch ไม่ได้ → ต้องเปิด ทั้งคู่ session.upload_progress.enabled=0 + memory_limit=-1 (security-php2.txt / PHP2Shell) — doctor จะ fail ถ้าไม่ครบ
  • path ใน ini ไม่ชี้ออกจากโฟลเดอร์ (copy ไปเครื่องอื่นได้จริง)
  • MariaDB bind localhost, local_infile=0
  • ไม่มี .sql / binary / โค้ดแอป ถูก track ใน git
  • IOC: memory-limit error ใน log (สัญญาณถูกเจาะ)
ก่อนขึ้น server จริง: เปลี่ยนรหัสผ่าน DB root · ตั้ง dbMode ให้ถูก · aptstack backup · aptstack service install · เปิด firewall เฉพาะที่จำเป็น
