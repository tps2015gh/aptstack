  At aptstack.ps1:1411  Get-ChildItem $inner -Force | Move-Item -Destination $dest -Force

กลไกที่พัง (Expand-AndFlatten)

Expand-Archive zip -> dest
  dest = { mariadb-10.4.8-winx64 }          # inner folder เดียว
  flatten: ย้ายลูก inner ขึ้น dest ทีละตัว
    Move-Item ถ้าชน/ล็อก → Windows แก้ด้วย copy แล้วค่อยลบ source
    ลบ source ติดล็อกที่ share\russian       # ล็อกชั่วคราว (AV/scan) 
    → pipeline หยุดกลางทาง → dest ครึ่งๆกลางๆ

สภาพที่ค้างอยู่จริง (inspection)

stack\mysql\10.4.8\
├─ bin\  data\  include\  lib\  share\        # ย้ายขึ้นมาได้บางส่วน (share ไม่สมบูรณ์)
└─ mariadb-10.4.8-winx64\                    # inner เหลือค้าง
   └─ share\, COPYING, CREDITS, README.md ... # ย้ายไม่หมดเพราะค้างที่ share\russian
─ .aptstack-source   # ไม่มี → Set-SourceMeta (ขั้นสุดท้าย) ยังไม่ถูกเรียก = ติดตั้งไม่เสร็จ
─ bin\mysqld.exe     # มี (ย้ายก่อน)  แต่ share\errmsg.sys ยังไม่มี
Dead-end ที่สอง: รอบถัดไปของ add mysql 10.4.8 เจอ Test-Path $dest → ตอบ "มีอยู่แล้ว" แล้วจบ — ผู้ใช้ซ่อมเองไม่ได้ด้วยคำสั่ง add (ต้อง rm mysql 10.4.8 ก่อน ถึงจะ add ใหม่ได้)

งานที่ต้องแก้ (backlog)

  1. Expand-AndFlatten — แตกไฟล์ลง temp แล้ว flatten ใน temp (ไม่ชนของเดิม) + retry/robocopy fallback รายไฟล์ + ข้อความไทยบอกชื่อไฟล์ที่ล็อกชัดเจน ห้ามค้าง dest ครึ่งๆกลางๆ
  2. ทางซ่อม — ถ้า dest มีอยู่แต่ยังไม่จบ (ไม่มี .aptstack-source) → ให้ re-add ทับได้ (แจ้งเตือนก่อน) แทนคำว่า "มีอยู่แล้ว"
  3. Alias — aptstack add mariadb <ver> = mysql (ตอนนี้ Normalize-PmaKind รับแค่ pma/phpmyadmin)
  4. เมนู interactive — เพิ่มหัวข้อ [MariaDB] ใน Select-Interactive (ตอนนี้มีแค่ [แอป] กับ [PHP]) เลือกแล้วเรียก Switch-MySql เหมือน PHP
หมายเหตุ: ดาวน์โหลด URL ของ mariadb ทำงานถูกต้องแล้ว (Get-OfficialUrls mysql → archive.mariadb.org) — ที่พังคือขั้น extract/flatten ไม่ใช่ขั้นโหลด

encoding/ภาษาไทยใน conf เพี้ยนตัดทิ้งconf ต้นฉบับกับ round-trip (UTF8+BOM) ให้ผลเดียวกัน (T3); บรรทัด 36 เป็น comment ไทยปกติ

4.3 ข้อเท็จจริงที่เหลืออยู่ (สนใจ technical สุด)

  • dlerror = "No error" — ข้อความนี้แปลว่า LoadLibrary คืน NULL โดยที่ GetLastError() = 0 ซึ่งเกิดได้ในเคส DllMain คืน FALSE (CRT/loader init ล้มเหลวใน process นั้นๆ) ต่างจาก dependency หายซึ่งจะได้ error 126 "The specified module could not be found"
  • php7ts.dll vs php8ts.dll — import แทบจะเหมือนกันทุกประการ ต่างที่ php7ts มี imagehlp.dll เพิ่ม (System32 — ไม่น่าใช่ปัญหา) และ php7 สร้างด้วย VC15/VS2017 (filename vc15) ส่วน php8.3 = vs16 — คนละ toolset
  • dll ทั้งคู่ import libapr-1 / libaprutil-1 / libhttpd / VCRUNTIME140 / api-ms-win-crt-* — ตัว httpd (Apache Lounge VS18, built ต.ค. 2026) ใหม่กว่า PHP 7.4.33 (built พ.ย. 2022) ราว 4 ปี
  • log apache-error.log จาก run ก่อนหน้ามีบรรทัด VirtualProtect() failed [87] The parameter is incorrect 2 ครั้ง ก่อน server จะยุติ — เป็นอาการคนละ run แต่คุ้มค่าต้องสอบต่อ (เกี่ยวกับการตั้งหน้าความจำของ mod_php/TS)

6.2 เจอเองจากโค้ด/คอนฟิก aptstack (code review ระหว่าง debug)

#ระดับพบรายละเอียด / แนะนำ
V1สูงphpMyAdmin config-auth + root/root เปิดจาก LAN ได้ Write-PmaConfig สร้าง config.inc.php เป็น auth_type='config' (user root/pass จาก stack.json = root) ไม่มีหน้าล็อกอิน ขณะที่ Listen 8077 (ไม่ระบุ IP → รับทุก interface) + Require all granted — ใครใน LAN ที่ถึง port 8077 เปิด /phpmyadmin/ เข้าเป็น root ทันที · แก้: เพิ่ม Require local สำหรับ /phpmyadmin หรือ Listen 127.0.0.1:8077 หรือบังคับ auth_type='cookie'
V2กลางไม่มี integrity check ไฟล์ที่ดาวน์โหลด add รับ URL อะไรก็ได้แล้วแตกเลย — ไม่เทียบ SHA256 กับค่าอ้างอิง (ทั้งที่ตัว dist ของ aptstack เองมี .sha256) · แก้: pin hash ของ official หรืออย่างน้อยโชว์ hash หลังดาวน์โหลดให้ user เทียบ
V3กลางcreds เริ่มต้น root/root + dbAdmin auto ผูก 127.0.0.1:3307 (ดี) แต่รหัสผ่าน default ง่ายมาก และ dbAdmin auto ให้ phpMyAdmin แชร์ creds เดียวกัน · แก้: สุ่มรหัสผ่านตอน setup แล้วบันทึกให้เห็นชัด
V4ต่ำExpand-AndFlatten ใช้ Expand-Archive ตรงๆ พึ่งพาการกัน path traversal ของ PowerShell — ควร validate รายชื่อ entry ใน zip ว่าไม่มี ../พาธเด็ดขาดก่อนแตก (zip-slip defense-in-depth) — ยังไม่พบ exploitable ในไฟล์ที่ใช้จริง เป็น hardening
V5ต่ำconfig/session files อยู่ใน config\sessions\ ตอนนี้ปลอดภัยเพราะ httpd.conf มี RedirectMatch 404 ^/(config|stack|...) กันไว้แล้ว — เพียงแต่ตำแหน่งนี้ "ต้องไม่โดนยกเลิก" เมื่อแก้ template

6.3 สิ่งที่ตรวจแล้วดี (ไม่พบรอบโหว่)

  • Options -Indexes ปิด directory listing ✓
  • RedirectMatch 404 ^/(config|stack|versions|data|logs|templates|bin)(/|$) กันโฟลเดอร์ระบบจากเว็บ ✓
  • FilesMatch ปฏิเสธ .bak/.ini/.log/.sql/.pem/.key/... ✓ (รวม config.inc.php ของ phpMyAdmin ด้วย .inc)
  • /server-status = Require local ✓ · Header nosniff + SAMEORIGIN ✓ · MariaDB bind 127.0.0.1 ✓
